# 固定命令基线验收分析

`x2 acceptance-report` 离线读取 `command_baseline_session.py` 的原始同步记录，重算驻留末尾的编码器结果；不初始化 ROS，不执行动作，不把发布统计作为运动成功证据。

```bash
uv run x2 acceptance-report \
  logs/20260929-fixed-baseline-joint.json \
  logs/20260929-fixed-baseline-002-confirmed.json
```

返回 JSON 包含每份原始文件 SHA256、采用的完整阈值、质量检查、运动检查、三段驻留窗口与重复性结论。退出码 0 仅表示所有输入满足单轴及重复性工程标准；3 表示分析成功但验收未通过/未齐全，2 表示输入无法读取或解析。任何结果都保留 `execution_authorized=false` 与 `hardware_acceptance_complete=false`。

## 判定依据与范围

先检查九个阶段事件完整且递增、四路源时间及接收时间递增、采样连续覆盖、无缓存丢弃/解析错误、URS 内站立 wire4/body1、故障码零、结束后的新鲜站立/臂/手反馈，以及上肢命令序号连续。两路命令都必须保留固定全臂基线，只允许选定关节在指定范围内变化；双手目标保持不变。HAL 在每段驻留末尾必须实际收到预期目标。

质量不合格输出 `inconclusive`，仍可保留可计算的诊断数值，但不据此声称通过。质量合格后，所有运动检查必须同时通过；否则输出 `fail`：

| 检查 | 默认工程阈值 |
| --- | --- |
| 驻留时长 / 分析窗口 | ≥0.8 s / 末尾0.2 s |
| 每路 HAL/编码器窗口样本数 | ≥10 |
| 上肢命令/HAL/编码器最大接收间隔（含首尾边界） | ≤0.05 s |
| MC 最大接收间隔及最终反馈龄 | ≤0.25 s |
| 命令偏离固定基线/预期目标 | ≤0.00001 rad |
| 选定轴编码器增量相对请求增量的误差 | ≤0.002 rad |
| 选定轴各驻留窗口的绝对位置误差 | ≤0.005 rad |
| URS 回位窗口相对基线编码器的残余 | ≤0.001 rad |
| 全程其余关节相对基线中位数的最大偏移 | ≤0.005 rad |
| 任一关节驻留窗口的峰峰值 | ≤0.002 rad |
| 至少三次合格重复中的位移/残余极差 | ≤0.001 rad |

这些是明确可复核的工程审查默认值，**不是厂商发布的精度指标**。可通过 `--criteria criteria.json` 指定字段覆盖，报告会完整保留最终取值；改变阈值不能被解释为控制器修复。默认阈值没有用于放宽既有实机安全配置。

重复性需要至少三份不同 SHA256、不重叠且处于同一 PC2 启动时钟范围的记录，关节、带符号幅度、固定 HAL 基线和阈值相同，每次均通过单轴检查。不同幅度不能拼成重复试验，重复提供同一文件也不算。工具不验证外部录入的机器人身份、MC 配置版本、负载、接触环境或操作者现场确认；因此即便 `pass_under_criteria` 也只是该组兼容数据的数值验收，不自动开放多轴或模型闭环。

回位窗口严格终止于 `recovery_complete`，不混入随后恢复 STAND_DEFAULT 的编码器数据。源 ROS 时间和接收单调时间分别检查，未声称传感器硬件同步，也不把 reported effort 当作已标定外力。
