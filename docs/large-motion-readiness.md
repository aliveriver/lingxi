# 大幅左肩请求：本地保护补强，未实机执行

后续软件契约更新：按用户指定保留0.01–1.0rad的幅度输入范围，常量与错误提示统一；测试改为覆盖正负0.5/1.0边界、相邻浮点数越界、非有限值及绝对关节限位。此修改解决旧0.02rad测试契约冲突，不代表0.5rad实机动作合格。部署与复测结果另存本轮独立证据目录；下文描述此前阶段。

2026-09-30 用户请求左肩+0.5rad，并将本机`validate_acceptance_delta`上限改成1.0rad。本轮保留用户的上限修改，没有部署它，没有运行实机动作。此前只读SSH核对时PC2仍为0.02rad；该记录不代表后续现场实时状态。

在本地固定基线入口补齐：

- `publish_points`可指定最大帧间隔。脚本固定50ms，检查覆盖定时等待后、反馈验证后及发送返回后。超时即抛出异常，不再继续发送后续目标；已经发送的帧保留在日志中。默认不改变其他调用方。
- 每次发送前在等待结束后读取臂反馈，验证完整14轴及顺序、domain严格为0、故障码严格为0、有限位置、接收龄0–100ms、每轴命令与编码器绝对误差。
- 新参数`--max-tracking-error-rad`必须显式提供有限正值，没有推测实机阈值；切模式前先校验基线，发送期再逐帧检查。它不是依据幅度自动放宽的阈值，也不会从编码器重建命令基线。
- 测试使用明确合成反馈和虚拟时间，验证编码器不动时不会继续累积到0.5rad，以及调度延迟、验证延迟、发送阻塞、末帧超时、未知故障、数据过期/未来时间、非目标轴误差等拒绝行为。

这些是Python软件检查，不能中断卡住的底层发送调用，不是硬实时看门狗或机器人制动系统。停止后续发送不等于机械臂立即停止，更不等于回位。

**尚未解决的现场协议问题：** 现有脚本异常处理仍请求STAND_DEFAULT，这是历史小步路径，未验证大幅偏离时的行为。未自行改成保持最后位置、追随编码器或直接撤回基线，因为这些选择会发送不同的实际控制目标。需要受支持的驱动/MC停止与恢复行为及适用跟随误差阈值，才能审查大幅试验的完整协议。当前补丁不是0.5rad测试放行。

既有幅度边界测试依照原0.02rad协议编写。用户修改为1.0rad后，它们的失败表示契约冲突，不能将旧421通过沿用到修改后的代码。本轮不通过删除这些测试或修改断言隐藏变化；新增保护测试独立报告。

没有部署补丁、修改MC/驱动增益、注入力矩、直连总线、切模式或新增运动。证据保存于`logs/large-motion-guards-20260930-120001/`，旧冻结包和历史证据保留。
