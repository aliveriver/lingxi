## 缺口一：掌根直装已确认，URDF坐标变换尚未定义

用户后续明确说明：“灵巧手的掌根直接安装在机器人的手腕上”。据此将本机机械连接方式记录为**O10掌根直接固定安装于机器人手腕**，不再将连接方式列为未知，也不假设存在额外转接机构。该说明来自用户，没有新的现场测量。

离线装配可据此采用腕部到掌根的固定连接，不增加活动自由度。仍需确定的是两份模型坐标系之间的数值关系：直接机械连接不意味着 `wrist_roll_link` 与 `l_palm` / `R_palm` 的URDF原点重合或轴向一致，因此不能仅据“直装”设置 `xyz=0 0 0、rpy=0 0 0`。左右具体平移和旋转应由对应坐标定义、安装图或完整装配模型给出。

官方v1.3.0和PC2 SDK v1.3.0的左右臂都止于 `left_wrist_roll_link` / `right_wrist_roll_link`，没有下接掌根的joint。O10独立文件根为 `l_palm` / `R_palm`，不包含X2腕部连接。

要把质量和COM变换到机械臂坐标，需要左右分别明确 `T_wrist_roll_link_from_palm`，即将掌根坐标变换到腕roll link坐标的刚性变换，还需确认实际安装部件（如护盖、螺钉）的质量归属；不凭空加入转接板。不能把两个根简单重合，也不能把手掌根、指尖TCP或全手COM混为一点。

v1.4的 `X2-Ultra_omnihand.urdf` 确实给出掌根固定joint：左 `xyz=[0,-0.001,-0.049] m, rpy=[0,3.14,1.58] rad`；右 `xyz=[0,0.001,-0.049] m, rpy=[0,3.14,-1.58] rad`。**它属于X2 Ultra -N的另一套模型**，且其中手的惯性、关节origin/axis/零位参数与独立O10不同，没有证据可以将这两个变换直接搬到本机。

这证明**直接数值映射不成立**，不证明实物越限。该日志的L/R关节标签可能由项目按官方索引补齐，不能将标签相似视为厂商模型坐标已一致。

仅在这一个历史姿态，对左手整体取反会使10个值落入独立模型范围；右手原值10/10在范围内，整体取反则9/10不在范围内。但“落入范围”既不能确认实际正方向，也不能辨识零位偏移，尤其不能确定拇指的坐标转换。**没有修改HAL发送/接收符号，也没有把取反规则固化到控制代码。** 后续若验证模型映射，转换应位于离线模型适配层；是否对应逆向控制映射还要独立验证。

独立左右手的拇指参数本身也不应简单镜像：左thumb roll范围约+2°至+73°，右约−30°至+40°；左thumb abad轴为 `[-0.087155,0,0.99619]`，右为 `[0,0.418896,-0.908034]`，且joint origin与局部坐标不同。文件中相异的局部轴不单独证明物理转轴不同，但必须连同origin旋转、关节零位一起推导，不能只对名字改前缀。

六个mimic轴不能当作额外命令自由度。左四指DIP跟随PIP的multiplier约−1.144444，右为+1.144444；两侧拇指PIP/DIP分别为MCP的1.33/1.3倍。左锁定中指关节的原名是 `l_middle_abad_jonit`（原文件拼写），不能误认为第11个主动轴。

官网 [AimDK末端接口](https://x2-aimdk.agibot.com/zh-cn/latest/Interface/control_mod/endeffector.html) 重新核对了HAL索引，但没有取得这两份独立URDF到Agi v1.1.4 HAL的完整符号/零位映射。官网链接的新版 [Agillink SDK](https://github.com/AgibotTech/agillink_omnihand_sdk) 提供O10关节角/0–4096执行器值转换及主动/被动轴展开API；本次只读其文档和头文件，未运行独立SDK或连接总线。接口存在不能证明它与当前X2 HAL使用同一坐标约定，也不能代替安装外参。旧 `Omnihand-2025-SDK` 链接本次返回404，失败记录已保留。

## 缺口三：手质量与现有腕部惯性不能直接叠加

| 模型条目 | 左侧 kg | 右侧 kg |
| --- | ---: | ---: |
| X2 Ultra v1.3.0 wrist roll link | 0.303040 | 0.303847 |
| X2 Ultra -N v1.4.0普通模型 wrist roll link | 0.338000 | 0.337000 |
| X2 Ultra -N v1.4.0灵巧手变体 wrist roll link | 0.081000 | 0.081000 |
| v1.4.0灵巧手变体掌根以下质量合计 | 0.447100 | 0.447100 |
| 官网O10独立手质量合计 | 0.534300 | 0.534300 |

集成模型掌部质量0.1594kg，独立手掌部为0.2175kg，差异并非仅是指尖虚拟link数量。整机灵巧手变体在增加hand树的同时调整腕部质量；这提示需要明确替换哪些聚合部件，但**不能据跨机型参数反推本机应减去多少质量**。

本机v1.3腕roll惯性已包含哪些末端部件仍未知。应向厂家取得v1.3+O10完整装配模型/惯性说明，或确认腕壳、实际安装件、手腕护盖/螺钉和手本体的部件分账后重新组合。用户确认掌根直装，并不能单独确定腕roll惯性是否已包含手部质量；不假设或添加额外转接板。没有直接增加0.5343kg，当前实机诊断的额外payload仍为0。

O10规格书的≤510g/≤520g分别对应普通/触觉款，且不含腕板护盖及螺钉；不能将0.5343kg模型合计解释为本机称重值。URDF中的质量和COM足以计算声明模型的静态重力，但手指姿态变化会改变全手COM；在角度映射和安装变换明确前，不能把其结果用于本机补偿。

另对照发现v1.4集成手拇指PIP的mimic推导端点约±1.137431rad，略超自身±1.134464rad限位约0.002967rad；独立O10模型未发现此矛盾。这是对照模型的端点不一致，不能据此改本机限位。

## 除重力外还可研究什么补偿

| 方向 | 能解决的误差 | 当前条件 |
| --- | --- | --- |
| 手、转接件、工具/物体负载补偿 | 附加质量产生的姿态相关静态力矩 | 仍属重力模型扩展；先解决上述坐标与质量分账，避免重复计重 |
| 摩擦/死区补偿 | 小步推不动、方向切换后残余等可能的静摩擦效应 | 现象相容但尚未确诊；需同轴双向数据辨识，不能从URDF或reported effort直接定值 |
| 零位、方向和运动学标定 | 恒定零偏、模型角度与编码器不一致、TCP误差 | 本次已确认手模型存在坐标不一致；先核对HAL是否已应用标定，避免重复校正 |
| 有界经验前馈表 | 同姿态/方向下可重复的系统偏差 | 需独立标定数据及留出验证，不能用一个姿态拟合后宣称泛化；不使用不断累积的外层积分 |
| 惯性/科氏等动态前馈 | 较快运动中的速度/加速度相关误差 | 当前缓慢小步试验不宜优先归因于此；还需可靠动态模型和受支持的底层接口 |

本次检查的机器人/O10 URDF没有 `joint/dynamics` 或 `joint/calibration` 条目，不提供已辨识摩擦、传动间隙或本机零位标定。即使字段存在也不能代替实测。MC/URS上层仍只有位置目标，不提供直接力矩/速度/增益通道；模型前馈若折算成位置偏置，仍依赖等效刚度假设和限幅，不能把它当成力矩控制。
